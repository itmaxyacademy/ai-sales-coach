# Audit 001: Anti-Slop and Ponytail

Date: 2026-09-29
Scope: current working-tree changes for session lifecycle, hints, language persistence, feature flags, the pre-session briefing, and manager replay. This is a static source review. No application source was changed during this audit.

## Anti-Slop findings

1. **HIGH - R-32, R-26: briefing is not an accessible dialog.** [Session page](../Frontend/app/karyawan/session/[sessionId]/page.tsx#L926) uses a visual overlay and a `section`, without dialog semantics, Escape handling, focus management, or disabling background controls. Keyboard users can move focus behind the overlay, and the only dismissal is the continue button. Use the existing dialog pattern or add the required keyboard and focus behavior.

2. **HIGH - R-35: browser delivery gate is unverified.** The briefing and replay were not run through a browser click-through in this audit. The prior TypeScript checks do not verify responsive layout, focus behavior, or that timeline selection works in the rendered page. Run the app and exercise these controls before treating the UI as shipped.

3. **MEDIUM - R-04: replay uses emoji as event markers.** [SessionTimelineReplay.tsx](../Frontend/components/session/SessionTimelineReplay.tsx#L70) marks events with 🚀, 🚨, and ⚡, which are generic decoration rather than product-specific labels. Replace them with clear text or meaningful state indicators.

## Additional correctness and feature-wiring findings

4. **P1 - briefing can leave an orphan active session.** [startSession](../Backend/src/controllers/sessionController.ts#L96) creates the active database session before the briefing appears. If the user closes the page before choosing “Mulai latihan”, the sweeper only finalizes sessions that reached `decided` or `maxTurns`, so this empty session remains active. The call-duration timer also starts before the briefing is dismissed. Show the briefing before creating the session, or add an explicit abandon path and start the timer after the user begins.

5. **P1 - an employee can change a shared course setting.** [updateSessionLanguage](../Backend/src/controllers/sessionController.ts#L758) verifies ownership of the session, then updates the course-wide `defaultLanguage` without checking the caller's role. One employee's toggle therefore changes the default seen by other users who have no prior session. Store a per-user preference or restrict course-default changes to course managers.

6. **P2 - feature flag values are unused.** `FEATURE_FLAGS` is only declared in [featureFlags.ts](../Frontend/app/featureFlags.ts#L12); no component imports it. The three environment variables therefore do not gate the voice features, which currently run independently of the flag values. Wire the flags into their feature entry points or remove the ineffective configuration.

7. **P2 - concurrent rejected hint requests still invoke the model.** [getHint](../Backend/src/controllers/sessionController.ts#L716) generates the AI hint before the atomic reservation at line 719. Parallel API requests can all incur model work even though the reservation later rejects all but the allowed request(s). Reserve under a per-session lock before generation, with a rollback or expiry path if generation fails.

8. **P2 - the stuck-session sweep can repeatedly inspect only the same first 50 rows.** [sweepStuckSessions](../Backend/src/controllers/sessionController.ts#L60) fetches 50 active sessions without ordering or pagination, then filters in memory. With more than 50 active sessions, due sessions outside that batch may be delayed indefinitely. Page through active sessions or query due states in bounded batches.
